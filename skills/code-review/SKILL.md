# 代码审查

你擅长审查 TypeScript / Node.js 项目。逐项对照清单检查，只报告有依据、可复现的问题，不要臆测或堆砌泛泛而谈的建议。

## 审查清单

### 安全性
- 命令注入：不要把关口未校验的输入拼进 shell 命令或 `bash` 调用。
- 路径穿越：读写文件前确认目标路径落在 workspace 之内。
- 敏感信息：不要把 token、密钥、`.env` 内容写进日志或提交。
- 依赖风险：新增依赖前确认来源可信、版本已锁定。

### 正确性
- 边界条件：空数组、空字符串、`undefined`、零值是否被正确处理。
- 异步与并发：是否漏掉 `await`，共享状态是否存在竞态。
- 错误处理：异常是否被吞掉，失败路径是否有明确结果。
- 类型安全：避免 `any` 与不安全断言，保持 strict 下的类型完整。

### 性能
- 循环内的 I/O 或重复读取：能否批量化或缓存。
- 是否存在不必要的全量拷贝与深比较。
- 同步阻塞调用是否挡在请求路径上。
- 算法复杂度是否与数据规模相匹配。

### 可维护性
- 命名是否表意，函数是否过长、嵌套是否过深。
- 重复逻辑是否应抽成公共函数。
- 死代码、未使用导入、过期注释。
- 注释是否解释「为什么」，而不是复述「做了什么」。

### 测试
- 新增行为是否有对应用例，关键分支是否覆盖。
- 是否断言了具体输出，而非只断言「不抛异常」。
- 测试是否依赖真实网络或外部状态。
- 是否为该 bug 补了可复现的回归用例。

## 输出格式

**Critical Issues**：必须修复的问题，逐条给出文件与行号、影响、修法。
**Improvements**：可选优化，按收益排序，简述理由。
**Verdict**：Ready to merge / Needs minor changes / Needs major revision。

## 常用命令

```bash
git diff HEAD~5 --stat            # 查看近期改动范围
grep -rn "TODO\|FIXME\|HACK" .    # 查找遗留标记
npm run check                     # 类型检查 + lint（本项目）
```
